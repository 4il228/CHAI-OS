# CORE_PLAN.md: Фаза 1 — Разработка управляющего ядра (chai-core)

## Подфаза 1.1: Инициализация структуры и архитектуры демона (Rust)

### 📋 Контракт спецификации
* **Входные данные:** Отсутствуют (чистый репозиторий).
* [cite_start]**Выходные данные:** Скомпилированный статический бинарник `chai-core`[cite: 14], базовая структура папок проекта, настроенный логгер.
* **Критерии успеха:** Команда `cargo build --release` производит статически линкованный исполняемый файл без зависимостей от динамических библиотек системы (`ldd chai-core` показывает `not a dynamic executable` или эквивалент для статики).

### 🤖 Инструкция по выполнению (Chain of Thought)
1.  **Создание проекта:** Инициализировать бинарный проект Rust (`cargo init --bin chai-core`).
2.  **Настройка Cargo.toml:** Добавить зависимости для асинхронного рантайма (`tokio` с фичей `macros` и `rt-multi-thread`), логирования (`tracing`, `tracing-subscriber`) и сериализации (`serde`, `serde_json`). Настроить профиль релиза для статической линковки через `target-feature=+crt-static` (или конфигурацию `.cargo/config.toml` для мускула/musl).
3.  **Архитектура логирования:** В `src/main.rs` инициализировать `tracing-subscriber`, выводящий логи в `stdout` в формате JSON (для последующего парсинга системным демпфером NixOS).
4.  **Точка входа:** Создать бесконечный асинхронный цикл в `main`, который ожидает сигнал завершения (`SIGINT`/`SIGTERM`) и корректно завершает работу.

## Подфаза 1.2: Реализация транспортного слоя JSON-RPC 2.0

### 📋 Контракт спецификации
* **Входные данные:** Проект из подфазы 1.1.
* [cite_start]**Выходные данные:** Локальный Unix Domain Socket (UDS) сервер, обрабатывающий спецификацию JSON-RPC 2.0[cite: 15].
* **Критерии успеха:** Успешный парсинг валидного JSON-RPC 2.0 запроса и возврат валидного JSON-RPC 2.0 ответа/ошибки через сокет `/run/chai-core/chai.sock`.

### 🤖 Инструкция по выполнению (Few-Shots паттерн)
1.  **Привязка к сокету:** Создать UnixListener по пути `/run/chai-core/chai.sock`. Реализовать обработку прав доступа (сокет должен быть доступен только пользователю `root` и группе `chai-shell`).
2.  **Парсинг протокола:** Написать DTO (Data Transfer Objects) структуры для JSON-RPC 2.0.
    * [cite_start]*Пример валидного запроса (Шаблон):* `{"jsonrpc": "2.0", "method": "execute_intent", "params": {"prompt": "string"}, "id": 1}` [cite: 15]
    * *Пример валидного ответа (Шаблон):* `{"jsonrpc": "2.0", "result": {"status": "accepted"}, "id": 1}`
3.  **Маршрутизатор (Router):** Создать пустую заглушку метода `execute_intent`. Если метод не найден, возвращать стандартную ошибку JSON-RPC: `{"jsonrpc": "2.0", "error": {"code": -32601, "message": "Method not found"}, "id": 1}`.

## Подфаза 1.3: Модуль интеграции с LLM (Ollama API и Cloud BYOK)

### 📋 Контракт спецификации
* **Входные данные:** Интерфейс запроса из подфазы 1.2. Конфигурационный файл `/etc/chai/config.json`.
* **Выходные данные:** Изолированный Rust-модуль `src/llm/client.rs`.
* [cite_start]**Критерии успеха:** Метод `Client::generate(prompt: &str)` успешно переключается между локальным эндпоинтом Ollama (`http://localhost:11434`) [cite: 60] [cite_start]и внешними API (OpenAI/Anthropic/Gemini) [cite: 62] в зависимости от флага в конфигурации, возвращая сырой текстовый ответ.

### 🤖 Инструкция по выполнению (Chain of Thought)
1.  **Чтение конфигурации:** Реализовать парсинг `/etc/chai/config.json`, содержащего структуру: `{"provider": "local" | "openai" | "gemini", "api_key": "string?", "model": "string"}`.
2.  [cite_start]**Реализация локального клиента:** Если провайдер `local`, отправлять POST-запрос через `reqwest` на `/api/generate` Ollama с фиксацией системного промпта (System Prompt)[cite: 60].
3.  [cite_start]**Реализация BYOK клиентов:** Если выбран облачный провайдер, подставлять соответствующие HTTP-заголовки авторизации (`Bearer token`) и эндпоинты нужного вендора (например, `api.openai.com/v1/chat/completions`)[cite: 62].
4.  **Обработка таймаутов:** Настроить жесткий таймаут сети (30 секунд для облака, 60 секунд для локальной модели). В случае ошибки сети возвращать строго типизированную ошибку `LlmError::ProviderUnavailable`.

## 1. Аннотация и философия системы
[cite_start]CHAI OS представляет собой полноценную операционную систему на базе дистрибутива NixOS, спроектированную для установки непосредственно на bare-metal (основной компьютер пользователя)[cite: 5]. 

[cite_start]Ключевая парадигма системы — полный отказ от ручного системного администрирования в пользу естественно-языкового промпт-интерфейса[cite: 6]. [cite_start]Пользователю не требуется знание конфигурационных файлов, синтаксиса языка Nix или флагов пакетного менеджера[cite: 7]. [cite_start]Взаимодействие осуществляется через встроенный ИИ-шелл как в GUI, так и в чистом TTY/CLI[cite: 8].

[cite_start]Пользователь описывает желаемое состояние системы на естественном языке, а резидентный ИИ-сервис выполняет следующие шаги[cite: 9]:
* [cite_start]Самостоятельно генерирует декларативные Nix-выражения[cite: 9];
* [cite_start]Разрешает зависимости и собирает систему[cite: 9];
* [cite_start]Активирует новые профили атомарно и без риска повреждения ОС[cite: 9].

## 2. Архитектура ядра и подсистем (декларативный рантайм)
[cite_start]Архитектура системы рассчитана на длительное использование в качестве основной ОС, что требует абсолютной стабильности и нулевого риска деградации от действий ИИ-агента[cite: 11]. [cite_start]База NixOS обеспечивает идеальный фундамент благодаря свойству иммутабельности[cite: 12].

### 2.1. Native Target Оркестратор (Rust Core)
[cite_start]Управляющее ядро системы `chai-core` скомпилировано статически на Rust и работает в фоне как системный демон[cite: 14]. Оно отвечает за:
* [cite_start]Прием команд из пользовательского ИИ-шелла через протокол JSON-RPC 2.0[cite: 15];
* [cite_start]Взаимодействие с локальной или облачной языковой моделью для трансляции намерений пользователя в декларативный Nix-код (`/etc/nixos/configuration.nix` или модули Flakes)[cite: 16, 17];
* [cite_start]Контроль сборки системы посредством `nixos-rebuild` и мгновенный откат изменений (`rollback`) на уровне загрузчика в случае сбоя[cite: 18].

### 2.2. Изолированная среда генерации Nix-выражений
[cite_start]Для генерации и валидации ИИ-скриптов разворачивается изолированный рантайм[cite: 22]. [cite_start]Ни один агент не имеет прямого доступа к модификации живой файловой системы в обход менеджера пакетов Nix, что гарантирует 100% защиту хоста от засорения и конфликтов библиотек[cite: 22].

## 3. Пользовательское пространство и ИИ-шелл (chai-shell)
[cite_start]Управление системой полностью перенесено из классических командных оболочек (Bash/Zsh) в специализированную интерактивную среду[cite: 24].

### 3.1. Нативный ИИ-Шелл (chai-shell) вместо Bash
[cite_start]Стандартный голый Bash-шелл полностью заменен на собственный `chai-shell`, написанный на Rust[cite: 26].
* [cite_start]**Работа без GUI:** Shell функционирует на самом глубоком системном уровне, являясь оболочкой по умолчанию как в графическом эмуляторе терминала, так и в чистой консоли (TTY) при полном отсутствии GUI[cite: 27, 28].
* [cite_start]**Промпт-режим:** По умолчанию командная строка ожидает ввод на естественном языке (например, ввод "покажи свободное место на диске" транслируется в системный вызов)[cite: 29, 30].
* [cite_start]**POSIX-префикс:** Сохраняется возможность выполнения стандартных POSIX-команд для опытных пользователей через префикс `!`[cite: 31].

### 3.2. Единый конвейер администрирования
[cite_start]При вводе запроса в `chai-shell` (или через глобальное окно `Super+Space` в GUI) процесс обработки выглядит следующим образом[cite: 33]:
1. [cite_start]**Анализ интента:** LLM разбивает промпт на дерево декларативных зависимостей (какие пакеты добавить, какие services включить в Nix-конфиг)[cite: 34].
2. [cite_start]**Синтез Nix-модуля:** Вместо генерации небезопасных bash-скриптов, ИИ генерирует чистый Nix-код[cite: 35].
3. [cite_start]**Превью (Dry-run):** Шелл выводит структурированный diff изменений (какие пакеты будут добавлены/удалены) для верификации пользователем[cite: 36].
4. [cite_start]**Атомарное применение:** После одобрения запускается `nixos-rebuild switch`, и изменения применяются атомарно[cite: 37].

### 3.3. Отказоустойчивость и Graceful Degradation
Ядро ОС функционирует независимо от агента; [cite_start]архитектура гарантирует работоспособность системы при недоступности LLM (падение локального демона, исчерпание лимитов API или потеря сети)[cite: 39, 40]. 
[cite_start]При сбое модели `chai-shell` автоматически переходит в режим классической диагностической POSIX-консоли[cite: 43]. [cite_start]Вместо генерации конфигураций шелл начинает транслировать пользователю системные логи об ошибке (`journalctl -xe`), предоставляя полную информацию для ручного исправления или перезапуска ИИ-сервиса[cite: 44].

## 4. Сетевой стек и безопасность
[cite_start]Поскольку ИИ делегировано управление конфигурацией Nix, реализована превентивная модель безопасности на уровне Ring 0 через подсистему eBPF LSM[cite: 46].

| Системный Модуль | Сфера Ответственности | Механизм Изоляции (Agent Access) |
| :--- | :--- | :--- |
| **Nix Store / Nix-Channel** | [cite_start]Установка софта, разрешение зависимостей [cite: 47] | Чтение и сборка дериваций. Полная изоляция процессов сборки в «песочнице» Nix (Sandbox). [cite_start]Блокировка подмены системных путей ядра. [cite: 47] |
| **NixOS Configuration** | [cite_start]Управление демонами, автозагрузка, сервисы [cite: 47] | eBPF-фильтрация. [cite_start]Агент может модифицировать только строго определенные файлы в `/etc/nixos/` или пользовательские флейк-модули, относящиеся к задаче. [cite: 47] |
| **Nix Profiles / Generational Rollback** | [cite_start]Глобальное состояние ОС [cite: 47] | Каждое переключение профиля (`nixos-rebuild`) автоматически создает новое поколение (Generation) в загрузчике. [cite_start]Откат к предыдущему состоянию системы гарантирован на 100% аппаратном уровне. [cite: 47] |

## 5. Конвейер исполнения (Execution Pipeline)
[cite_start]Архитектурный конвейер выполнения команд состоит из следующих шагов[cite: 51]:

```

[Запрос Юзера в chai-shell / TTY]
│
▼
Парсинг Намерений (LLM) 
│
▼
Генерация декларативного Nix-кода 
│
▼
Анализ рисков безопасности (eBPF Core) 
│
▼
Вывод diff конфигурации в chai-shell (Human-in-the-Loop) 
│
▼
Одобрение оператором 
│
▼
Сборка новой деривации Nix (Автоматическое создание Generation) 
│
▼
Атомарная активация профиля (nixos-rebuild switch) 

```

## 6. Требования к ресурсам и структура инференса
[cite_start]ОС предоставляет пользователю абсолютный контроль над слоем инференса[cite: 59]:
* [cite_start]**Оффлайн (Локальный по умолчанию):** Ollama-демон развернут как системный сервис NixOS[cite: 60]. [cite_start]Загружается модель уровня Qwen-2.5-Coder[cite: 60]. [cite_start]При наличии GPU веса проецируются напрямую в VRAM[cite: 61].
* [cite_start]**Облачный BYOK (Bring Your Own Key):** Динамическая подмена провайдера на внешние API (OpenAI, Anthropic, Google Gemini)[cite: 62].

## 7. Установка и Bootstrap (Bare-Metal)
[cite_start]Установка системы полностью автоматизирована через ИИ[cite: 67]. [cite_start]Загрузочный образ (ISO) стартует сразу в минималистичном интерфейсе `chai-shell` в текстовом режиме ТТY[cite: 67]:

1. [cite_start]Пользователь пишет прямо в консоли запрос (например: *"Установи систему на весь диск NVMe, зашифруй его, создай пользователя chai_user и настрой оболочку Hyprland"*)[cite: 68].
2. [cite_start]Установочный ИИ-агент самостоятельно парсит разметку диска, генерирует конфигурацию аппаратной части (`hardware-configuration.nix`), прописывает настройки LUKS шифрования, описывает менеджер разделов и базовые пакеты в `configuration.nix`[cite: 69].
3. [cite_start]Запускается `nixos-install`[cite: 70]. [cite_start]После перезагрузки стартует готовая к работе ОС с резидентным оркестратором `chai-core` и дефолтным интеллектуальным `chai-shell`[cite: 70].
